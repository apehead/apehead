# AGENTS.md

apehead's GitHub profile README: "The Catacombs of Legacy", a choose-your-own-adventure made of nested
`<details>` and animated pixel-art SVGs, generated by Node scripts (no dependencies). Published to the
public repo `apehead/apehead`.

## Project map

- `src/quest/` — the game
  - `story.mjs` — all game text and the story graph (nodes, choices, deaths, relics, intro)
  - `engine.mjs` — shared kit: pixel font `ptext()`, sprite renderer, `scene()`, `dialogue()`, HUD,
    relic/death banners, animation helpers (API documented in its header comment)
  - `sprites.mjs` — cast, portraits and relic icons as string-grid sprites
  - `scenes/<id>.mjs` — one module per scene, `export default function render()`
- `src/adventure.mjs` — renders every scene + banners and generates the game README into `variants/adventure/`
- `src/lib.mjs` — helpers shared by all generators (fonts, `writer()`, pixel ape)
- `src/<slug>.mjs` + `variants/<slug>/` — ~30 earlier prototype pages (local only, not published)
- `README.md`, `assets/` — the published copy of the game (generated by `publish.mjs`; never hand-edit)
- `QUEST.md` — game design source of truth (story, cast, colours, mechanics)
- `BRIEF.md` — persona, tone, ape rule, SVG constraints, verified agent vocabulary (local only)

|---|---|
| `node build.mjs [slug ...]` | Build all variants, or only the named ones (`node build.mjs adventure`) |
| `node publish.mjs` | Build the game and copy it to the root `README.md` + `assets/` |

| `gh api markdown -f mode=gfm -f text="$(cat variants/adventure/README.md)"` | See exactly what GitHub's sanitizer keeps |
</important>

<important if="you are changing game text, choices, deaths or relics">
- Edit `src/quest/story.mjs`, never the generated READMEs. Keep narration to ≤3 short lines per node.
- The build fails on unbalanced tags, 4-space-indented lines, a node without exactly one surviving
  choice, or a death count other than `DEATH_COUNT`.
</important>

<important if="you are changing how choices are ordered or rendered in src/adventure.mjs">
- The surviving choice always renders last. It contains the rest of the game (so nobody can skip ahead),
  and any option listed after it would appear below the whole nested story. The user rejected both
  alternatives: a separate "Onward" section (cheatable) and an "earlier choices" log at the bottom (confusing).
- Puzzle art must agree with that order: the honest chest is III, the door's correct gem order is listed last.
</important>

<important if="you are writing README HTML or markdown for the game">
- Exclusive choices: sibling `<details name="ch-<node>">` (GitHub keeps `name`, prefixed with `user-content-`).
- Wrap images in `<picture>` so GitHub doesn't auto-link them to the raw file.
- Outcome cards are one-cell `<table>`s (the only bordered box GitHub keeps).
- GitHub strips `style`, classes and scripts; `> [!TIP]` alerts don't render inside `<details>`;
  markdown inside `<details>`/`<td>` needs blank lines around it.
- Restart link: `https://github.com/apehead?quest=restart` (a different URL reloads and collapses everything).
</important>

<important if="you are creating or editing SVG scenes or banners">
- Inside `<img>` on GitHub: no `<script>`, no external URLs or web fonts, no `<foreignObject>`; CSS keyframes and SMIL only.
- Essential content must be visible without animation (never start text or art at opacity 0 / scale 0).
- 900 wide, self-backgrounded, under ~150 KB. Prefix your own `def()` ids with the scene id.
- The pixel font is uppercase with a limited glyph set; `ptext()` throws on unknown characters (e.g. `$`).
- Dialogue: speakers come from `SPEAKERS` in the engine; ≤2 lines, width-checked by the build; use
  `bubble()` for a third voice.
</important>

<important if="you are writing copy or adding characters, art or new pages">
- The ape rule: an ape (the ape paladin, in the scene's own style) appears in every scene.
- He is a principal engineer, not a framework fan: no tech-stack lists; jokes about engineering and agents.
- Use the agent vocabulary in `BRIEF.md`. Never name the authors of the frameworks it draws on (listed in `BRIEF.md`) on public pages. Avoid
  "inner loop", "deterministic agents", "can't make mistakes" and dogmatic "spec first".
</important>

<important if="you are committing, pushing or publishing to GitHub">
- The repo is public and is his profile page: confirm with the user before pushing.
- `.gitignore` is a whitelist (root README, `assets/`, build/publish scripts, `src/lib.mjs`,
  `src/adventure.mjs`, `src/quest/`). Keep `BRIEF.md`, `QUEST.md`, prototypes and previews out.
- Run `node publish.mjs` before committing so `README.md` and `assets/` match the source.
</important>
